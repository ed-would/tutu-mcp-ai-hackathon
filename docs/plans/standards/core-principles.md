# Core principles

**Purpose:** High-level principles for any AI-assisted development workflow.

**Non-goals:** File layouts → `structure-and-naming.md`. Shape of
`AGENTS.md` → `architecture-and-docs.md`. Full SDD/TDD →
`spec-driven-development.md`, `testing-and-verification.md`. Cursor
product surfaces → `.cursor/`.

**Owner:** Project maintainers · **Scope:** Shared agent principles and context
**Status:** Active · **Last reviewed:** 2026-08-12

## Principles

- **Agent-friendly:** Organise the repo so agents understand structure and
  conventions without repeated explanation.
- **KISS and YAGNI:** Use the smallest architecture that satisfies the current
  requirement; do not add speculative layers.
- **Single source of truth:** Keep each fact in one canonical place; elsewhere
  link to it.
- **Clear entry points:** Humans start at `README.md`; agents start at
  `AGENTS.md` and its linked documents.
- **Progressive disclosure:** Keep root instructions small; put detail in
  `docs/`, `specs/`, or an on-demand skill.
- **Spec-driven development (SDD):** For non-trivial work, written specs under
  `specs/` are the primary agent input. Workflow → `spec-driven-development.md`.
- **Verification before done:** Agents MUST NOT claim completion without evidence
  (`docs/agents/verification.md`, `testing-and-verification.md`).
- **Docs co-located with code:** Plans, decisions, and standards live in the repo,
  not only in chat.

## Neutral repository artifacts

Agents MUST NOT add product-neutral branding such as `Made with Cursor`,
`Generated by Cursor`, or equivalent generated-by labels to code, documentation,
or commit messages unless the owner explicitly requests it.

## Context and session hygiene

- Agents MUST attach the **minimum sufficient context**: a relevant section,
  symbol, or linked file rather than an unbounded dump.
- Use repository references (file paths, symbols, and specs) instead of pasting
  whole documents when the host supports references.
- Phase broad work through the written plans and specifications described in
  `spec-driven-development.md`; keep exploration separate from implementation
  when the context becomes noisy.
- Store repeated instructions in `AGENTS.md`, this standards folder, or an
  on-demand tool skill. Do not restate them in every session or command.
- Start a fresh session when the task changes domain, the context is too large,
  or the agent begins contradicting an earlier decision; re-anchor on `AGENTS.md`
  and the relevant canonical documents.

## Anti-duplication rule

Each fact or procedure MUST have one canonical home. Other documents may give a
short pointer, but MUST NOT maintain a subtly different copy. When a contract,
architecture choice, or workflow changes, update its canonical spec/decision and
then repair references and adapters.

## Language policy (this repo)

- Product, research, specs, and decisions: **Russian**
- `AGENTS.md` and `docs/standards/`: **English**
- File/folder names, frontmatter keys, and code identifiers: **English**
